# robr0 Design System

A design system that treats design decisions as data. Every colour, space, radius, and typographic choice is a token — defined once, referenced everywhere. The result is a codebase where changing a single variable updates the entire system.

</div>

<div className="ds-section">

## Philosophy

<div className="ds-principles">
  <div className="ds-principle">
    <h4>Tokens over magic numbers</h4>
    <p>No hardcoded values in components. Every visual property traces back to a named token with a clear purpose. If you can't name it, it shouldn't exist.</p>
  </div>
  <div className="ds-principle">
    <h4>Semantic, not literal</h4>
    <p>Components don't know they're teal or 8px — they know they're a primary action or a small gap. Swap the primitives underneath and themes change without touching a single component.</p>
  </div>
  <div className="ds-principle">
    <h4>Composition over configuration</h4>
    <p>Small, focused components that combine freely. A table cell holds any content — text, icons, buttons, inputs — because it accepts React nodes, not a fixed set of props.</p>
  </div>
  <div className="ds-principle">
    <h4>Two sizes, not infinite</h4>
    <p>Every component supports default and compact. No medium, large, extra-large. Constraints force consistency and reduce decision fatigue.</p>
  </div>
</div>

</div>

<div className="ds-section">

## Architecture

The system flows in one direction: raw values become purposeful tokens, tokens become components, components become pages.

<div className="ds-layers">
  <div className="ds-layer">
    <div className="ds-layer-label">Primitives</div>
    <p>The raw scale — colours, spacing values, border widths, radii. These are the atoms. Never referenced directly by components.</p>
  </div>
  <div className="ds-layer-connector" />
  <div className="ds-layer">
    <div className="ds-layer-label">Semantic tokens</div>
    <p>Purpose-driven mappings. A primitive becomes "action primary background" or "text secondary". Light and dark themes are just different mappings over the same primitives.</p>
  </div>
  <div className="ds-layer-connector" />
  <div className="ds-layer">
    <div className="ds-layer-label">Components</div>
    <p>React components that consume semantic tokens via CSS custom properties. Theme-aware by default — no conditional logic, just token references.</p>
  </div>
  <div className="ds-layer-connector" />
  <div className="ds-layer">
    <div className="ds-layer-label">Application</div>
    <p>A Next.js site that imports tokens once and uses components directly. Theme switching is a single data attribute on the root element.</p>
  </div>
</div>

</div>

<div className="ds-section">

## Theming

Light and dark aren't separate systems — they're alternate readings of the same token layer. Components never know which theme they're in. They reference semantic tokens, and the theme decides what those tokens resolve to.

<div className="ds-theme-grid">
  <div className="ds-theme-card ds-theme-light">
    <h4>Light</h4>
    <p>Neutral backgrounds, dark text, teal accents. Semi-transparent layers for depth.</p>
  </div>
  <div className="ds-theme-card ds-theme-dark">
    <h4>Dark</h4>
    <p>Same token names, different primitives. Surfaces darken, text lightens, accents persist.</p>
  </div>
</div>

Action tokens use semi-transparent rgba values so interactive elements get natural glass-like layering with backdrop blur — no opaque paint required.

</div>

<div className="ds-section">

## Conventions

<div className="ds-conventions">
  <div className="ds-convention">
    <strong>BEM naming</strong>
    <span>{"Block__element--modifier with a ds- prefix. .ds-button, .ds-button__icon, .ds-button--compact."}</span>
  </div>
  <div className="ds-convention">
    <strong>Size variants</strong>
    <span>Default and compact. Default uses paragraph tokens (16px), compact uses paragraph-sm (14px) with tighter padding.</span>
  </div>
  <div className="ds-convention">
    <strong>Icons</strong>
    <span>Material Symbols Rounded at 24px default, 20px compact. Custom SVGs where font metrics cause alignment issues.</span>
  </div>
  <div className="ds-convention">
    <strong>Typography scale</strong>
    <span>Display, heading, sub-display, title-body (600), paragraph-em (500), paragraph (400), paragraph-sm. Each is a full token set: family, size, weight, line-height, letter-spacing.</span>
  </div>
  <div className="ds-convention">
    <strong>Local fonts</strong>
    <span>All fonts are self-hosted — no external CDN dependencies. Nunito Sans for text, Material Symbols for icons.</span>
  </div>
</div>

</div>
